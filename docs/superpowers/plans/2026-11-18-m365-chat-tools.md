# Microsoft 365 Chat Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude answers employees' work questions from the handbook and from their own SharePoint/OneDrive files, mail, and Teams messages, citing each source with a link (issue #34).

**Architecture:** `/api/chat` keeps auth, validation, rate limit, and the topic check. On-topic questions then go to one Claude agent run by the SDK tool runner (`client.beta.messages.toolRunner`, `stream: true`). Its tools are `search_handbook` (wraps today's retrieve → re-rank → threshold) plus read-only Microsoft 365 tools that call Graph with the signed-in user's token from `getGraphAccessToken()`. Every item a tool returns is registered under a short id (`p1`, `f1`, `m1`, `t1`); Claude cites `[id]`, the marker filter strips it, and the registry turns cited ids into `citation` events. The wire format doesn't change.

**Tech Stack:** Next.js 16 route handler, `@anthropic-ai/sdk` 1.8.0 (`betaZodTool`, `toolRunner`), Zod 4, Microsoft Graph v1.0 REST via `fetch`, existing pdf.js parser, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-12-internal-knowledge-chat-design.md`, section *Microsoft 365 data*, plus issue #34. Decisions made with the product owner on 2026-11-18: tools defined in `/api/chat` (no MCP server); one agent with all tools, the handbook search included; files read as full text.

## Global Constraints

- Read-only Graph calls only. No send, post, or write endpoint anywhere.
- The Graph token comes only from `getGraphAccessToken()` per request; never logged, never returned, never shared between requests or users.
- Never log question, answer, passage, or Microsoft 365 text (file names, subjects, senders, snippets included). Errors are logged with `describeError`; throw `SafeError` with status and Graph error code only, never Graph's message or body.
- Search text never goes in a URL: every search uses `POST https://graph.microsoft.com/v1.0/search/query`. HTTP telemetry records URLs (`src/lib/telemetry.ts`, `http: { enabled: true }`).
- Microsoft 365 content is never sent to Voyage.
- Grounding: every claim cites an id; an answer citing nothing is outcome `dont-know`. HR policy comes from the handbook.
- Exact dependency versions; no new dependencies (Graph via `fetch`).
- Absolute `@/` imports, ≤100 lines per function, colocated `*.test.ts`, mock only boundaries (`fetch`, Anthropic client, `next/headers`).
- Microsoft 365 tools stay off in prod until #2 records the retention decision: they're offered only when `M365_TOOLS=enabled` (set in dev, not prod). Without it the agent gets `search_handbook` only.
- `CHAT_MODEL` default stays `claude-opus-5-5`, `output_config: { effort: "medium" }`, `betas: ["server-side-fallback-2026-07-01"]`, `fallbacks: "default"`, system prompt cached.

## Review Focus

1. A Graph 429 with a long `Retry-After` (e.g. 120 s) while someone is waiting: fail that tool call fast with a "busy, try again" tool error instead of sleeping. Pinned in Task 1.
2. Auth bypass / no Graph token: Microsoft 365 tools answer "Microsoft 365 isn't available in this session" as a tool error and the handbook still works. Pinned in Task 4.
3. A huge file or mail body: tool output is capped (`TOOL_TEXT_MAX = 20_000` chars, noted as cut) so one read can't blow the context or `max_tokens`. Pinned in Tasks 2 and 3.
4. Claude cites an id that no tool returned in this request (made up, or from an earlier turn): ignored, never a citation. Pinned in Task 5.
5. The agent loops on tools: `max_iterations: 8`; a run that stops on `tool_use` or `max_tokens` ends with the existing cut-off error, not a half answer marked `answered`. Pinned in Task 5.

### Task 1: Graph request helper

**Files:**
- Create: `src/lib/graph/client.ts`
- Test: `src/lib/graph/client.test.ts`

**Interfaces:**
- Produces:
  - `export const GRAPH_BASE = "https://graph.microsoft.com/v1.0"`
  - `export type FetchFn = (url: string, init: RequestInit) => Promise<Response>` (later tasks import it from here)
  - `export type GraphFailure = "unauthorized" | "forbidden" | "not-found" | "throttled" | "unavailable" | "failed"`
  - `export class GraphError extends SafeError { readonly failure: GraphFailure; readonly status: number }` — message `Graph <METHOD> <path without query> failed: status=<n> code=<graph error.code or "unknown">`
  - `export interface GraphRequestOptions { token: string; method?: "GET" | "POST"; body?: unknown; headers?: Record<string, string>; fetchFn?: FetchFn; sleep?: (ms: number) => Promise<void> }`
  - `export async function graphRequest(path: string, options: GraphRequestOptions): Promise<Response>` — `path` starts with `/`.
  - `export async function graphJson<T>(path: string, options: GraphRequestOptions): Promise<T>`

Behaviour (ported from sales-portal `src/lib/sharepoint/graphClient.ts`, tightened for interactive use and privacy): at most `MAX_ATTEMPTS = 3`; 429 and 5xx are retried; wait `Retry-After` seconds when present, else `2 ** attempt * 250` ms; if `Retry-After` exceeds `MAX_WAIT_SECONDS = 5`, fail at once with `throttled`; `AbortSignal.timeout(10_000)` per attempt; 401 → `unauthorized`, 403 → `forbidden`, 404 → `not-found`, 429 exhausted → `throttled`, 5xx exhausted → `unavailable`, other 4xx → `failed` (not retried). Error code read from `{ error: { code } }` in the JSON body; the body is otherwise discarded.

### Task 2: SharePoint/OneDrive files and mail tools' Graph calls

**Files:**
- Create: `src/lib/graph/m365-item.ts`, `src/lib/graph/files.ts`, `src/lib/graph/mail.ts`
- Test: `src/lib/graph/files.test.ts`, `src/lib/graph/mail.test.ts`

**Interfaces:**
- Consumes: `graphJson`, `graphRequest`, `GraphError` (Task 1); `parsePdf(bytes: Uint8Array): Promise<ParsedDocument>` from `@/knowledge/pdf`.
- Produces (in `m365-item.ts`):
  - `export const TOOL_TEXT_MAX = 20_000`
  - `export type M365Kind = "file" | "mail" | "teams"`
  - `export interface M365Item { kind: M365Kind; ref: string; title: string; location: string[]; url: string; lastModified: string /* ISO date-time */; text: string }` — `ref` is what the matching read tool takes (`"<driveId>/<itemId>"`, message id, or Teams ref from Task 3); `location` is the citation's section path, at least one entry (e.g. `["OneDrive", "Clients", "Acme"]`, `["Mail", "From Jane Doe"]`).
  - `export function capText(text: string): string` — cuts at `TOOL_TEXT_MAX` and appends `\n[cut: the rest of this item is not shown]`.
- Produces (in `files.ts`): `searchFiles(query: string, token: string, fetchFn?: FetchFn): Promise<M365Item[]>` (snippet in `text`), `readFile(ref: string, token: string, fetchFn?: FetchFn): Promise<M365Item>` (full text in `text`).
- Produces (in `mail.ts`): `searchMail(query, token, fetchFn?)`, `readMail(ref, token, fetchFn?)` with the same shapes.

Graph calls:
- Files search: `POST /search/query` body `{ requests: [{ entityTypes: ["driveItem"], query: { queryString: query }, from: 0, size: 10 }] }`; map `hitsContainers[0].hits[]` → `resource.name`, `resource.webUrl`, `resource.lastModifiedDateTime`, `resource.parentReference.driveId` + `resource.id` as ref, `hit.summary` (strip `<c0>`/`<ddd/>` highlight tags) as text.
- File read: `GET /drives/{driveId}/items/{itemId}?$select=name,webUrl,lastModifiedDateTime,file,parentReference` for metadata, then `.pdf` → `/content`; `.md`/`.txt`/`.csv` → `/content` as text; `.docx`/`.pptx`/`.xlsx`/`.doc`/`.ppt` → `/content?format=pdf`; anything else → `GraphError`-free tool message "This file type can't be read". PDF bytes → `parsePdf` → sections joined as `## heading path\ntext`; then `capText`.
- Mail search: `POST /search/query` with `entityTypes: ["message"]`, size 10; map `resource.subject`, `resource.from.emailAddress.name`, `resource.receivedDateTime`, `resource.webLink`, `resource.id`, `hit.summary`.
- Mail read: `GET /me/messages/{id}?$select=subject,from,toRecipients,receivedDateTime,body,webLink` with header `Prefer: outlook.body-content-type="text"`; text = `From`, `To`, `Date` lines + body, `capText`.

Before writing the mappers, check the response shapes against the Graph docs for `searchRequest` (driveItem, message) and `message`; record any field that differs in this plan.

  - Microsoft 365 tools are included only when `process.env["M365_TOOLS"] === "enabled"`; otherwise `chatTools` returns `[search_handbook]` alone. Test both.
